# Стандарт контента — предложение

> Черновик от 2026-10-20. После утверждения переносим в `docs/content-format.md` и `docs/shop-schema.md`.

## 1. Сквозной контекст: backend интернет-магазина

Во всём направлении Backend ученик — **backend-разработчик одного и того же интернет-магазина**. Каждый курс — это новая часть его работы над проектом. Задачи формулируются как рабочие запросы: «менеджер просит выгрузку», «тимлид просит исправить», «упал сервер». Абстрактных примеров (котики, `foo/bar`, `a = 5`) нет.

| Шаг | Курс | Роль ученика в проекте | С чем работает |
|---|---|---|---|
| 10 | Python | пишет бизнес-логику магазина | товары, корзина, заказы как структуры Python → классы → async-сервисы |
| 20 | Linux | заходит на сервер магазина | `/srv/shop` (код), `/var/log/shop` (логи), `/etc/nginx` (конфиги) |
| 30 | Git | ведёт репозиторий магазина | фича «промокоды», ветки, конфликт в `settings.py`, PR |
| 40 | SQL | работает с БД магазина напрямую | учебная БД «магазин» (`shop-schema.md`) |
| 50 | Django ORM | те же таблицы через модели Django | приложение `shop`: `User`, `Product`, `Order`… |
| 60 | SQLAlchemy | пишет отдельный сервис отчётов по той же БД | те же таблицы через `DeclarativeBase` |
| 70 | Docker | упаковывает магазин в контейнеры | Django + Postgres + Nginx в compose |
| 80 | Nginx | выводит магазин в продакшен | прокси на Gunicorn, статика, фото товаров, HTTPS, кэш каталога |

Правила контекста:
- Данные везде одни и те же: в Python товар — это `dict`/класс с полями из таблицы `products`, в Linux лог — это запросы к страницам этих товаров, и т. д.
- Сущности и поля берём **только** из `shop-schema.md`. Нужно новое поле — сначала добавляем его в схему.
- Деньги — `Decimal` (Python) и `numeric` (SQL), никогда не `float`. Это часть обучения, а не мелочь.

### Что предлагаю добавить в схему магазина
Без этого не покрыть темы курсов (сейчас в `docs/drafts/shop-schema.md` их нет):
| Добавить | Для каких тем |
|---|---|
| `profiles` (1:1 с `users`: `phone`, `birth_date`) | связь 1:1 в SQL, `OneToOneField`, `relationship(uselist=False)` |
| `tags` + `product_tags` (простое N:M без доп. полей) | `ManyToManyField` без `through` (а `order_items` — пример с `through`) |
| `products.attributes jsonb` (цвет, размер) | тема JSONB в SQL |
| `promo_codes` (`code UNIQUE`, `discount_percent`, `valid_until`) | сквозная фича для Git, задачи на `CHECK`, даты, UPSERT |

## 2. Уровни сложности
- Каждый **раздел** курса имеет уровень: ●○○ основы → ●●○ применение → ●●● продвинутое. Разделы идут от простого к сложному.
- Каждая **задача** имеет `difficulty` 1–3, независимый от уровня раздела.
- Первые разделы курса — короткие уроки (5–7 минут чтения), задачи в одно действие. Последние — уроки до 12 минут, задачи, которые комбинируют несколько тем.

## 3. Из чего состоит тема
**Тема = 1 урок + 3–5 задач.** Урок всегда одной структуры:

```markdown
---
title: LEFT JOIN
level: 2                 # 1–3, уровень раздела
reading_time: 7
---

## Задача из магазина
Менеджер просит список покупателей, которые зарегистрировались, но ничего не купили.
INNER JOIN их не покажет — разберёмся почему.

## Как это работает
Теория маленькими шагами. Каждое понятие — пример кода + его результат
(таблица, вывод, дерево файлов).

## Сравнение            ← если в теме есть альтернативы (таблица)

## Частые ошибки
- Ошибка → почему происходит → как правильно.

## Итого
- 3–5 пунктов.

## Вопросы на собеседовании
2–4 вопроса с короткими ответами (на сайте — свёрнуты).
```

**Задачи темы — «лесенка»:**
| № | Сложность | Что проверяет |
|---|---|---|
| 1 | 1 | повторить пример из урока на других данных |
| 2–3 | 2 | применить тему к новому рабочему запросу |
| 4–5 | 3 | совместить с прошлыми темами курса |

**Темы без живого выполнения в браузере** (потоки, блокировки БД, systemd, HTTPS, деплой) отмечены в картах как «теория». Для них задачи другого типа — нужно согласовать с «Разработкой»:
- `quiz` — выбор ответа / порядок шагов;
- `fix` — «найди и исправь ошибку» в коде или конфиге, проверка по правилам или тестам.

## 4. Как устроены карты курсов
Все файлы `content/_plan/<курс>.md` имеют одну структуру:
- шапка: контекст курса, тренажёр, источники;
- разделы с уровнем ●○○/●●○/●●●;
- в каждом разделе таблица: `# | Тема | Что разбираем | Задача из магазина | Сырьё`;
- «Сырьё»: ✅ есть конспект · 🟡 частично · ❌ пишем с нуля · ⚠️ проверить/исправить в источнике · (теория) — без задач в тренажёре.
