Виды JOIN

Данные о пользователях и заказах лежат в разных таблицах. JOIN собирает их в одну строку результата — вопрос только в том, что делать со строками, у которых нет пары.

Как это работает

База берёт каждую строку левой таблицы и ищет ей пару в правой по условию ON. Тип JOIN определяет, что делать, если пары нет.

ТипСтроки без пары слеваСтроки без пары справа
INNER JOINотбрасываютсяотбрасываются
LEFT JOINостаются, справа NULLотбрасываются
RIGHT JOINотбрасываютсяостаются, слева NULL
FULL JOINостаютсяостаются

Пример

sql
SELECT u.email, o.id AS order_id
FROM users u
LEFT JOIN orders o ON o.user_id = u.id;
emailorder_id

Частая ошибка. Условие на правую таблицу в WHERE превращает LEFT JOIN в INNER: строки с NULL отфильтруются. Переносите такое условие в ON.

Итого

  • INNER — только пары; LEFT — все слева, даже без пары.
  • «Найти строки без пары» = LEFT JOIN + IS NULL.
  • Условия на правую таблицу при LEFT JOIN — в ON.

Раздел 7 · Производительность

Индексы и EXPLAIN ↗1

Почему мой индекс не работает — разбор вчера

Как проверить

Смотрю план запроса через EXPLAIN ANALYZE. Если вижу Seq Scan по большой таблице — индекс не используется. Index Scan или Bitmap Index Scan — всё ок.

EXPLAIN ANALYZE
SELECT * FROM orders
WHERE user_id = 42;

Когда индекс НЕ используется

  1. Функция над колонкой: WHERE lower(email) = '…' — обычный индекс по email не поможет. Нужен индекс по выражению: CREATE INDEX ON users (lower(email)).
  2. LIKE с % в начале: LIKE '%ноут' — B-tree бессилен, LIKE 'ноут%' — работает.
  3. Таблица маленькая — планировщику быстрее прочитать всё подряд. Это нормально, не баг.
  4. Выбирается большая часть строк (например, status = 'paid' у 90% заказов) — тоже Seq Scan.
  5. Разные типы: сравниваю int с text — индекс игнорируется.

Составной индекс

Индекс (user_id, created_at) работает для:

  • WHERE user_id = 1 ✓
  • WHERE user_id = 1 AND created_at > … ✓
  • WHERE created_at > … ✗ — левая колонка не указана

Запомнить

Индекс на каждую колонку — плохая идея: каждый индекс замедляет INSERT и UPDATE и занимает место. Индексирую то, по чему реально ищу и что видно в медленных запросах.

Вопросы

Нужно ли что-то устанавливать?

Нет. PostgreSQL и Python запускаются прямо в браузере. Первый запуск движка занимает несколько секунд, дальше — из кэша.

Мой код отправляется на сервер?

Нет. Запросы и программы выполняются у вас в браузере. На сервер уходят только прогресс и заметки, если вы вошли в аккаунт.

Что такое шпаргалки?

Ваши заметки, собранные по курсам и темам. Пишете заметку справа от урока, задачи или в тренажёре — она сама попадает в шпаргалку курса.

Кто видит мои заметки?

Только вы.

Зачем регистрироваться?

Чтобы прогресс и шпаргалки были на всех устройствах. Без аккаунта они хранятся в этом браузере.

Как предложить задачу или исправление?

Контент лежит в открытом репозитории — присылайте Pull Request или пишите в Telegram.
